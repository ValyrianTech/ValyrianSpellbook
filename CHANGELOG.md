# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Breaking

- `RunCommandProcess` (`helpers/runcommandprocess.py`) no longer runs commands through a shell (previously `Popen(..., shell=True)`, now `shlex.split` + `Popen(..., shell=False)`). As a result, shell features are no longer supported for string commands: pipes (`|`), redirection (`>`, `>>`, `<`), command chaining (`&&`, `||`, `;`), `$VAR`/`${VAR}` environment-variable expansion, command substitution (backticks / `$(...)`), glob expansion (`*`, `?`, `[...]`), subshells (`(...)`) and brace expansion (`{...}`).
  - Metacharacters are now passed as literal arguments (previously they silently misbehaved).
  - `RunCommandProcess` logs a `WARNING` by default when a string command contains shell metacharacters, and raises a `ValueError` when constructed with `strict=True`.
  - To keep shell features, invoke a shell explicitly by passing an argv list such as `['sh', '-c', '...']` or `['bash', '-lc', '...']`, or refactor the command to avoid shell features.
- `WebhookAction` (`action/webhookaction.py`) no longer follows HTTP redirects: `requests.get` and `requests.post` are now called with `allow_redirects=False` for both GET and POST webhook requests (previously `requests` followed redirects by default). This is SSRF hardening to prevent a webhook endpoint from redirecting the outbound request to an internal/private address that would bypass the SSRF-safe URL validation. As a user-visible result, a webhook endpoint that responds with a 3xx redirect is no longer followed to its final destination; the redirect response (a non-200 status) is instead treated as a webhook failure and the action returns a failure result. Users who rely on webhook endpoints that redirect must update their webhook configuration to point directly at the final destination URL.

### Fixed

- `btc2satoshis` (`helpers/conversionhelpers.py`) now converts its input to a `decimal.Decimal` via `Decimal(str(btc))` and computes `(value * 100_000_000).to_integral_value(rounding=ROUND_DOWN)` instead of mixing float math with manual string parsing, so negative and fractional inputs no longer lose value and binary-float truncation no longer biases amounts down by a satoshi (e.g. `btc2satoshis(0.29)` could previously return `28999999`). It also raises `TypeError` with message `Invalid type for btc: ...` for unsupported types and malformed numeric strings such as `'not_a_number'` (which previously could raise other errors), while retaining the existing `ValueError` when a string contains more than one `.`.

- All remaining outbound HTTP requests now use explicit timeouts so a slow or unresponsive remote endpoint can no longer hang a server worker. A new shared module `helpers/http_helpers.py` exports `DEFAULT_HTTP_TIMEOUT = 10` (used for ordinary requests) and `STREAM_HTTP_TIMEOUT = (5, 300)` (connect, read; used for streaming LLM requests). `DEFAULT_HTTP_TIMEOUT` is now passed as the `requests` timeout in `helpers/bip44.py`, `helpers/configurationhelpers.py`, `helpers/feehelpers.py`, `helpers/lnbitshelpers.py`, `helpers/twitterhelpers.py`, and the CLI HTTP helpers in `spellbook.py` (`do_get_request`/`do_post_request`/`do_delete_request`), while `STREAM_HTTP_TIMEOUT` is passed in `helpers/self_hosted_llm.py` and `helpers/textgenerationwebui_llm.py`.

- `RunCommandProcess.run()` now drains `stdout` and `stderr` concurrently using a separate thread per stream (each joined before the process is awaited), instead of reading `stdout` fully and then `stderr` sequentially. This prevents the child process from deadlocking when it produces enough `stderr` output to fill the pipe buffer while `stdout` is still being read.

- Resolved all remaining ruff lint errors; the repository is now lint-clean.
- Resolved all remaining mypy type-check errors; the repository is now type-check clean.
- Nonces are no longer lost on server restart, and concurrent requests can no longer bypass replay protection.
- Fixed `SendTransactionAction.configure()` (`action/sendtransactionaction.py`) so the configured `change_address` is written to `self.change_address` instead of overwriting `self.receiving_address`. Previously a supplied change address was silently ignored (change always returned to the sending address) and, when both a receiving address and a change address were configured, the change address would overwrite the intended receiving target, potentially sending the primary payment to the wrong address.
- Base58Check checksum validation for address/private-key decoding is now performed explicitly (raising `TypeError` for non-`str` input and `ValueError` for too-short or invalid-checksum data) instead of using a bare `assert`, so the validation is no longer stripped away under Python's optimized mode (`-O` / `PYTHONOPTIMIZE=1`). The duplicated `b58check_to_bin` implementations in `helpers/privatekeyhelpers.py` and `transactionfactory.py` were consolidated into `helpers/py3specials.py`; invalid Base58Check input now raises `ValueError`/`TypeError` rather than `AssertionError` in callers such as `PrivateKey` and `get_privkey_format`.
- Replaced a bare `assert` in `add_op_return()` (`transactionfactory.py`), which enforces that a transaction contains at most one OP_RETURN and only when the other outputs send funds, with an explicit check that raises `ValueError`. Because Python removes `assert` statements under optimized mode (`-O` / `PYTHONOPTIMIZE=1`), the invariant was silently not enforced in production under `-O`; it is now enforced regardless of the optimization level, and invalid input raises `ValueError` instead of `AssertionError`.
- Replaced the bare `assert` statements in `sign_and_verify()` and `sign_data()` (`helpers/messagehelpers.py`), which verify a message signature immediately after signing, with explicit checks that raise `ValueError('Signature verification failed')`. Because Python removes `assert` statements under optimized mode (`-O` / `PYTHONOPTIMIZE=1`), the signature verification check was silently disabled in production under `-O`; it is now enforced regardless of the optimization level, and a failed verification now raises `ValueError` instead of `AssertionError`.
- `WebhookAction.run()` (`action/webhookaction.py`) now passes an explicit 10-second `timeout` to `requests.get`/`requests.post` and handles `requests.RequestException` (network errors) by logging the error and returning a failure result instead of raising.
- `WebhookAction.configure()` now rejects non-public webhook URLs via the SSRF-safe `valid_webhook_url` validator, so SSRF-unsafe URLs are rejected at configuration time.
- `save_to_json_file` (`helpers/jsonhelpers.py`) now writes atomically: it writes to a temporary file in the same directory (via `tempfile.NamedTemporaryFile` with `delete=False`), flushes and `fsync`s it, then atomically renames it over the destination with `os.replace()` (removing the temp file on error). This prevents readers from seeing a partially-written or corrupt JSON file and prevents data loss if the process dies mid-write.
- `load_from_json_file` (`helpers/jsonhelpers.py`) now reopens the file on each retry attempt instead of reusing the original file handle, so a retry after a failed read can actually succeed (previously the exhausted/closed handle made retries fail unconditionally).
- `load_last_nonces()` (`authentication.py`) now treats a missing nonce file as a normal first-run condition: it logs at DEBUG level and creates an empty `json/private/last_nonces.json` via `save_last_nonces()`, instead of logging a spurious ERROR on every process start.
- Fixed `get_medium_priority_fee`, `get_low_priority_fee`, and `get_high_priority_fee` (`helpers/feehelpers.py`) so that per-byte rates are no longer computed via truncating integer division (`int(fee_per_kb / 1024)`), which truncated sub-1024 sat/kB estimates to 0 sat/byte and rounded every non-exact-multiple estimate down. Rates are now computed with `math.ceil` and clamped to a new `MIN_SAT_PER_BYTE = 1` minimum via a shared `_per_byte` helper, so a sub-1024 or zero estimate returns at least 1 sat/byte. The switch from truncation to `math.ceil` also rounds every non-exact-multiple estimate UP rather than down, which raises the effective per-byte fee for all non-exact-multiple estimates (not just the sub-1024 case) — for example 10000 sat/kB now yields 10 sat/byte instead of 9. This increases the fees paid by callers that use these helpers directly, such as `SendTransactionAction.run()`, which uses the result as `satoshis_per_byte`.
- Fixed the Web UI session secret key (`webui/config.py`) being regenerated on every process start, which invalidated existing sessions on restart and was not shared across multiple worker processes. The key is now sourced from the `SPELLBOOK_SESSION_SECRET` environment variable when set and non-empty, otherwise from a persisted file at `configuration/session_secret.key` (generated on first access via `secrets.token_hex(32)` with file permissions `0o600`, then reused), so sessions now survive restarts and work across workers. `SESSION_SECRET_KEY` is now a property on `Settings` rather than a class attribute.
- The Web UI server-side session store (`webui/auth.py`) is now file-backed and shared across worker processes instead of process-local in-memory. Session records are persisted as one JSON file per session id under `configuration/webui_sessions/` (written atomically with a temporary file, flushed/fsynced, `chmod 0o600`, then `os.replace`d into place), so sessions are visible across multiple worker processes and survive restarts. The public `SessionStore` API (`create`/`get`/`delete`, opaque `session_id` via `secrets.token_urlsafe(32)`, 24-hour TTL with lazy purge, no-op delete) is unchanged.
- Fixed the Web UI `is_authenticated` (`webui/auth.py`) check so the signed session cookie is no longer trusted on its own. A request is now only considered authenticated when both the cookie's `authenticated` flag is truthy and a matching, non-expired record exists in the server-side `_SESSION_STORE` for the cookie's `session_id`. When the cookie flag is set but the store record is missing, expired, deleted, or corrupt (e.g. after a restart or when a record has been purged), `is_authenticated` clears the stale client session (forcing the user back to `/login`) and returns `False`, so it can no longer disagree with `get_api_client` (which already returned an unauthenticated client when the record was absent). Previously a stale cookie could still show the dashboard while every API call failed for lack of credentials.
- Fixed block explorer HTTP calls so they can no longer hang indefinitely or propagate network errors. A new shared `DEFAULT_TIMEOUT = (5, 15)` (connect, read) constant was added in `data/blockexplorers/explorer_http.py`, and every `requests.get`/`requests.post` call in the block explorer clients (`data/blockexplorers/blockchain_info.py`, `blockstream.py`, `blocktrail_com.py`, `btc_com.py`, `chain_so.py`, `insight.py`) now passes `timeout=DEFAULT_TIMEOUT`. The explorer clients now also catch `requests.RequestException` alongside the previously caught `ValueError`, `KeyError`, `TypeError`, and `OSError`, so connection/timeout/HTTP errors are logged and returned as an error dict instead of being raised. Previously an unresponsive explorer could block a request indefinitely and `requests` timeout/network exceptions were uncaught.
- Fixed `authentication_required` (`decorators.py`) so authentication failures now return an HTTP 401 (Unauthorized) response with a JSON body instead of HTTP 200. Previously the decorator returned a plain `{'error': ...}` dict without setting `response.status`, so Bottle responded with HTTP 200 even when `check_authentication` did not return `AuthenticationStatus.OK` (missing/invalid API key, bad signature, or replayed nonce). It now sets `response.status = 401` and `response.content_type = 'application/json'` on failure, and applies `@wraps(f)` to preserve the decorated function's metadata. Clients can now detect authentication failures via the status code.

- Fixed `query()` (`data/data.py`) so it no longer raises a `TypeError` when no block explorers are configured or when an unknown explorer is requested. When `get_explorers()` returns `None` (no explorers configured) the function now logs an error and returns `{'error': 'No block explorers configured'}`, and when the request-supplied explorer (the `EXPLORER` global set via `set_explorer()`) is not among the configured explorers it logs an error and returns `{'error': 'Unknown explorer: <name>'}`. Previously both cases iterated over an unexpected value (e.g. `None`) and crashed with a `TypeError`; callers now receive a structured error dict instead.
- Fixed several unauthenticated REST API endpoints (`spellbookserver.py`) that read required fields directly from the JSON request body (e.g. `int(request.json['block_height'])`, `request.json['xpub']`), which raised unhandled `KeyError`/`TypeError` exceptions and surfaced as HTTP 500 responses when the JSON body was missing, not an object, or lacked a required field. Two new helpers — `_require_json_field(name, cast=None)` (returns a required field, optionally cast, raising `ValueError` when the body is missing/not an object or the field is absent) and `_require_xpub_field()` (returns an `xpub` validated against `validators.validators.valid_xpub`, raising `ValueError` when missing or not a valid extended public key) — now guard `get_sil`, `get_profile`, `get_sul`, `get_lal`, `get_lbl`, `get_lrl`, `get_lsl`, `get_random_address_from_sil`, `get_random_address_from_lbl`, `get_random_address_from_lrl`, and `get_random_address_from_lsl`. As a result, malformed requests to these endpoints no longer crash with an unhandled HTTP 500, and the `xpub` argument on the LAL/LBL/LRL/LSL and random-address-from-lbl/lrl/lsl endpoints is now validated as a valid extended public key.
- Fixed the address REST API routes (`spellbookserver.py`) so the address path segment now accepts the digit `0`: the route regex for `/spellbook/addresses/<address:re:...>/...` endpoints was widened from `[a-zA-Z1-9]+` to `[a-zA-Z0-9]+`. Previously the `0` digit was excluded, causing valid bech32 addresses containing `0` (e.g. `bc1qar0srrr7xfkvy5l643lydnw9re59gtzzwf5mdq`) to fail routing. This affects the `/transactions`, `/balance`, `/utxos`, `/SIL`, `/profile`, `/SUL`, `/LAL`, `/LBL`, `/LRL`, `/LSL`, and `/random/{SIL,LBL,LRL,LSL}` endpoints.
- Fixed `use_explorer` (`decorators.py`) so the global explorer state set via `set_explorer` is always cleared, even when the wrapped function raises an exception. The call to the wrapped function is now inside a `try/finally` block so `clear_explorer()` runs on every path (previously it only ran on the normal path, leaking the explorer state into subsequent requests), and `@functools.wraps(f)` is applied to the inner function so the decorated function's metadata (`__name__`, `__doc__`, etc.) is preserved instead of being replaced by `decorated_function`. The explorer value is now read via `get_last_explorer()` inside the `try` and attached to the result dict after the `finally` block, so the global state is cleared before the value is written to the return value.

### Security

- Fixed a CORS misconfiguration in the REST API's `enable_cors` decorator (`spellbookserver.py`). It previously set `Access-Control-Allow-Origin: *` together with `Access-Control-Allow-Credentials: true`, which is invalid and a latent credential-leak risk for the admin/RPC endpoints. The decorator now reads a new comma-separated `allowed_origins` option from the `[RESTAPI]` section of the configuration file (via the new `get_cors_allowed_origins()` helper in `helpers/configurationhelpers.py`), echoes the request's `Origin` header back as `Access-Control-Allow-Origin`, and sets `Access-Control-Allow-Credentials: true` and `Vary: Origin` only when the origin is in the configured allow-list (otherwise no CORS origin/credentials headers are set). `Access-Control-Allow-Methods` is now `GET, POST, PUT, DELETE, OPTIONS, HEAD` and `Access-Control-Allow-Headers` now includes `Authorization`.
- Fixed a path-traversal vulnerability in the custom-script loader. Previously, `valid_script` only checked that a `.py` file existed under `spellbookscripts/` or `apps/` by joining the user-supplied script name directly onto those roots, and the loader in `trigger/trigger.py` independently re-derived the script path and module name from the raw name. A script name containing `..` segments (e.g. `../../some_other_package/module.py`) or an absolute path could therefore resolve outside the allowed roots and load an arbitrary module. Script resolution is now centralized in a new `find_script_path` validator (`validators/validators.py`) that returns the absolute, real (`os.path.realpath`) path only when it lives inside `spellbookscripts/` or `apps/`, rejecting `..` segments, absolute paths and symlinks that escape those roots; `valid_script` delegates to it. `trigger/trigger.py` now derives both the script path (`find_script_path`) and the importable module name from the resolved path relative to the project root, instead of re-implementing the lookup.
- The REST API request logger (`spellbookserver.py`) no longer writes secrets to the request log: sensitive header values (`API_Key`, `API_Sign`, `API_Nonce`, `Authorization`, `Cookie`) and sensitive JSON body fields (such as `api_key`, `api_secret`, `secret`, `private_key`, `mnemonic`, `xpriv`, `password`, `passphrase`, `seed`) are now redacted to `********` before being logged, so API credentials and other secrets are no longer captured in request logs. Header matching is normalization-aware (`_is_redacted_header` lower-cases the name and converts underscores to hyphens) so the redaction actually applies to Bottle/WSGI's normalized header spelling (`Api-Key`, `Api-Sign`, `Api-Nonce`, `Authorization`, `Cookie`); a naive exact-match against the raw `API_Key`/`API_Sign`/`API_Nonce` spelling would silently fail to redact.
- Fixed an authentication bypass on the REST API `get_reveal` endpoint (`spellbookserver.py`). The endpoint that returns the reveal-secret value for a `RevealSecretAction` is now protected by `@authentication_required`, so it can no longer be called without a valid API key/signature.
- Fixed an unauthenticated information-disclosure vulnerability on the REST API `get_explorers` endpoint (`spellbookserver.py`). Previously, `get_explorers` served the `/spellbook/explorers` endpoint with no authentication and disclosed the list of configured explorer identifiers (the `data.get_explorers()` result is a list of explorer-id strings, not explorer configuration dicts, so no API key or other secret was ever exposed). The endpoint is now protected by `@authentication_required`, so it can no longer be called without a valid API key/signature. The Web UI API client (`webui/api_client.py`, `get_explorers`) now calls `self._request('GET', '/spellbook/explorers', authenticate=True)` so the dashboard sends its API credentials for this endpoint.
- Fixed a command-injection vulnerability in `spellbookserver.py` (`convert_aac_to_opus`) by removing `shell=True` and passing an argv list to `subprocess.run` (`shell=False`). ffmpeg failures are now surfaced as a `ValueError` (with the decoded stderr) instead of being silently swallowed.
- Fixed a command-injection vulnerability in `action/commandaction.py` (`CommandAction.run`) and `helpers/runcommandprocess.py` (`RunCommandProcess.run`) by removing `shell=True` from command execution.
- Commands are now executed via `shlex.split` + `subprocess.run(..., shell=False)` / `Popen(argv, ...)`, so shell metacharacters in commands and substituted placeholders are no longer interpreted by a shell.
- `CommandAction` now `shlex.quote`s placeholder values before substitution, so untrusted placeholder values cannot inject shell syntax.
- Fixed a command-injection vulnerability in `helpers/setupscripthelpers.py` (`spellbook_call`, `bitcoinwand_call`) by removing `shell=True` from command execution; commands are now passed as an argument list and run with `Popen(args, ..., shell=False)` (the now-unused `format_args` helper was removed from `helpers/platformhelpers.py`).
- Fixed a command-injection vulnerability in `helpers/notify_transaction.py`, which previously built a `curl` shell command from unsanitized CLI arguments (`url`, `pr`, `txid`) and ran it via `Popen(..., shell=True)`. The script now sends the notification with a direct `requests.post(..., json=..., timeout=10)` call (`raise_for_status()` on the response), so no shell is involved and untrusted arguments can no longer inject commands. The file is no longer omitted from coverage in `.coveragerc`.
- `AESCipher` (`AESCipher.py`) now uses authenticated AES-GCM encryption with a salted, slow `scrypt` key-derivation function instead of the previous unauthenticated AES-CBC with PKCS7 padding and a single-round SHA-256 key derivation.
  - Fixes the lack of integrity/authentication: the version byte and salt are authenticated via the GCM tag, so tampering with the ciphertext, tag, salt or version byte is now detected and decryption fails with a `ValueError`.
  - Removes the padding-oracle exposure of the old PKCS7 padding, and the slow `scrypt` KDF makes brute-forcing the wallet password expensive.
  - New ciphertexts use a versioned v2 format (version byte, salt, nonce, tag, ciphertext), and legacy encryption is no longer produced. For backward compatibility, `decrypt()` still reads legacy v1 (AES-CBC) ciphertexts: a payload is tried as v2 first, and one that is not authenticated as v2 is retried as legacy v1 when it is structurally a legacy payload (16-byte IV plus a positive multiple of the 16-byte AES block).
    - The legacy read path returns a decoded UTF-8 string, so a legacy payload whose plaintext is not valid UTF-8 cannot be returned by `decrypt()`.
- Fixed the API nonce replay protection in `authentication.py` to be concurrency-safe and persistent:
  - A module-level `threading.Lock` (`_NONCE_LOCK`) guards the nonce read-modify-write, so the check-and-update of `LAST_NONCES` is atomic and safe under the threaded Bottle server (previously the in-memory nonce map was not protected against concurrent requests).
  - Nonces are now persisted to `json/private/last_nonces.json` via `load_last_nonces()` and `save_last_nonces()`; the file is loaded at import time, so replay protection survives server restarts.
  - The signature is verified before the nonce is recorded (using `hmac.compare_digest`), so an invalid signature can no longer poison the nonce store.
- `validate_credentials` (`webui/auth.py`), which authenticates Web UI logins, now compares the supplied API key and API secret to the configured values using `hmac.compare_digest` on UTF-8-encoded bytes (via `str(...).encode("utf-8")`) for both the key and the secret, instead of the previous non-constant-time `==` string comparison. This removes a timing side-channel on the Web UI login path that could in principle allow recovery of the API credentials by measuring comparison time. Authentication behavior is unchanged: valid credentials still authenticate and invalid credentials still fail. A unit test (`unittests/webui/test_auth.py`, `test_uses_compare_digest`) verifies that `validate_credentials` calls `hmac.compare_digest` for both the key and the secret.
- Webhook URLs configured on `WebhookAction` are now validated with an SSRF-safe `valid_webhook_url` validator (`validators/validators.py`) that rejects URLs resolving to private, loopback, link-local, reserved, multicast, or unspecified addresses (e.g. `10.0.0.0/8`, `127.0.0.0/8`, `169.254.0.0/16`, `0.0.0.0`, `::1`), preventing server-side request forgery against internal services.
- Hardened `WebhookAction` against DNS-rebinding and redirect-based SSRF: `WebhookAction.run()` now resolves the webhook URL via the new `resolve_and_validate_webhook_url` validator immediately before sending the request and pins the outbound connection to that pre-resolved public IP using a `PinnedIPAdapter` (a `requests.adapters.HTTPAdapter` subclass mounted on a `requests.Session`, preserving the original `Host` header and TLS SNI `server_hostname`). Redirects are now disabled (`allow_redirects=False`) for both GET and POST. This closes a time-of-check-to-time-of-use gap where the hostname could re-resolve to a private address between validation and the request.
- Fixed a SQL identifier injection risk in `helpers/mysqlhelpers.py`: database names interpolated into `CREATE DATABASE` and `USE` statements are now validated against an allow-list pattern and quoted with backticks via a new `_quote_identifier` helper, so unsanitized identifiers can no longer inject SQL.
- API keys and secrets generated by `initialize_api_keys_file()` (`authentication.py`) are now created with the cryptographically secure `secrets` module (`secrets.choice`) instead of the non-cryptographic `random` module, and are now 32 characters long (up from 16), drawn from ASCII letters and digits (`string.ascii_letters + string.digits`). The hard-coded `/spellbook/configuration/spellbook.conf` path was also replaced with a path derived from the module location (`PROGRAM_DIR`/`CONFIGURATION_FILE`).
- Fixed a path-traversal / arbitrary-local-file-read vulnerability in the Send Email action (`helpers/mailhelpers.py`). Previously the email template name (plus `.html`/`.txt`) and the image/attachment filenames were joined directly onto the `email_templates/` and `apps/` roots, so a name containing `..` segments or an absolute path could resolve outside those directories and cause an arbitrary local file to be read into the outgoing email (as an inline image or attachment). Template, image, and attachment paths are now resolved with a shared `_resolve_within` helper that `os.path.realpath`s the candidate and only accepts it when it stays inside the allowed directory and is an existing file; escaping or missing files are rejected (templates fail the send, images/attachments are skipped with an error log). Additionally, `sendmail()` now validates every comma-separated recipient against `valid_email` and returns `False` without sending when a recipient is missing or invalid.
- Centralized path resolution across action/trigger config access (get/save/delete/activate), the Send Email attachment/template resolver, and the custom-script loader through a new shared, fail-closed `safe_path` helper (`helpers/pathhelpers.py`). `safe_path(base_dir, candidate)` resolves a candidate path against a trusted base directory and rejects (`ValueError`) `None`, non-string, or empty candidates, `..` path segments, absolute paths, and any path that (after `realpath`/symlink resolution) escapes the base directory, returning the canonical resolved path otherwise. `Action.save()` and `Trigger.save()` now resolve their output file via `safe_path`, and `get_action_config`/`delete_action` (`helpers/actionhelpers.py`) and `get_trigger_config`/`delete_trigger`/`activate_trigger` (`helpers/triggerhelpers.py`) now use `safe_path`, so invalid (traversal/absolute/non-string) action/trigger ids are handled gracefully — getters return an empty dict and delete/activate return an error dict (`{'error': f'Unknown action id: ...'}` / `{'error': f'Unknown trigger id: ...'}`) — rather than being joined directly onto the config directory. See also the existing path-traversal fixes for the custom-script loader and the Send Email action.
- `safe_path` (`helpers/pathhelpers.py`) now intentionally rejects *any* candidate containing a `..` path segment, including internal `..` segments such as `foo/../bar` that would resolve back inside the base directory. This is stricter than a pure containment/escape check: such candidates are rejected even when they would stay within the base. As a result, a nonexistent traversal path passed to `_resolve_script_path` (e.g. `foo/../bar.py`) is now reported with the `'resolved_outside_roots'` reason instead of `'not_found'`, because the `..` segment is rejected by `safe_path` before any existence check. This behavior is intentionally stricter and is not fully preserved for `..` inputs.
- Hardened the Web UI session secret key (`webui/config.py`) against session forgery when the key file exists but is empty. Previously, if `configuration/session_secret.key` existed but was still empty after all retry attempts (for example, a previous writer crashed before writing its key), `SESSION_SECRET_KEY` returned an empty string, which would let an attacker forge sessions. It now generates a fresh `secrets.token_hex(32)` key and persists it atomically via a new `_atomic_write_secret` helper (temporary file flushed/fsynced, `chmod 0o600`, then `os.replace`d into place, with the temp file removed on failure). If a non-empty secret still cannot be obtained, the property now fails closed with a `RuntimeError` instead of returning an empty string.
- The Web UI no longer stores API credentials in the signed session cookie. On login, the API key and secret are stored server-side in a thread-safe, in-memory session store (`webui/auth.py`) keyed by an opaque `session_id` (generated with `secrets.token_urlsafe(32)`), and only that `session_id` is placed in the signed session cookie. Records expire after 24 hours (`SESSION_TTL_SECONDS = 86400`) and are lazily purged on access; logout deletes the record. This closes a vulnerability where the signed (but not encrypted) session cookie carried the API key and secret in the clear.
- The Web UI session cookie (`webui/main.py`) is now set with `SameSite=Strict` and can be made HTTPS-only via the `SPELLBOOK_SESSION_HTTPS_ONLY` environment variable (opt-in, accepts `1`/`true`/`yes`/`on`, case-insensitively).
- The Web UI 500 error handler (`webui/main.py`) no longer returns exception details to the client: it logs the exception server-side (`logger.exception(...)`) and renders a generic error page (the raw `error` block was removed from `webui/templates/errors/500.html`), instead of exposing `str(exc)` to the browser.
- The REST API `sign_message` endpoint (`spellbookserver.py`) no longer logs the full request body, which previously included the caller-supplied `private_key` in plaintext; the handler now logs only the request's `address`.
- Outbound streaming LLM requests no longer disable TLS certificate verification by default. The self-hosted LLM client (`helpers/self_hosted_llm.py`, `SelfHostedLLM`) and the text-generation-webui LLM client (`helpers/textgenerationwebui_llm.py`, `TextGenerationWebuiLLM`) previously called `requests.post(..., verify=False, ...)`, unconditionally disabling TLS certificate verification for all outbound streaming LLM requests. Both clients now call `requests.post(..., verify=ca_bundle, ...)` where `ca_bundle` comes from the new `get_llm_ca_bundle()` helper (`helpers/configurationhelpers.py`), which reads the new `ca_bundle` option from the `[LLMs]` section of `configuration/spellbook.conf`. When the option is absent or empty, `get_llm_ca_bundle()` returns `True`, so `requests` verifies against the system certificate store (verification is now ON by default); setting the option to a path uses that CA bundle for verification (e.g. to trust a self-signed certificate for a locally-hosted LLM server). A (blank by default) `ca_bundle =` option was added to the `[LLMs]` section of `configuration/example_configuration_file.conf`.
- Removed the `--wallet-password` command-line argument from the `hot_wallet.py` CLI (its `add_key`, `delete_key`, `set_bip44`, and `show` subcommands), which previously exposed the wallet password in process listings (argv). The wallet password is now read from the `SPELLBOOK_WALLET_PASSWORD` environment variable (falling back to an interactive `getpass` prompt) via a new internal `_get_wallet_password()` helper, used for both loading (decrypting) and saving (encrypting) the hot wallet, so the password is never passed on the command line. This is a breaking CLI change: users should set the `SPELLBOOK_WALLET_PASSWORD` environment variable instead of `--wallet-password`.
- Fixed a memory-exhaustion denial-of-service vulnerability in the REST API file-upload endpoints `upload_file` (`/spellbook/upload`) and `transcribe` (`/spellbook/transcribe`) in `spellbookserver.py`. Previously each handler read the entire uploaded file into memory via `uploaded_file.file.read()` before checking `len(file_content) > max_file_size`, so an attacker could send a very large upload and exhaust server memory before the size check rejected it. Both handlers now perform a cheap pre-check against the advertised `Content-Length` header (`request.content_length`), rejecting oversized requests early with HTTP 413 when the client declares a size over the limit, and read the body with a bounded `uploaded_file.file.read(max_file_size + 1)` (the `+1` detects overflow), so the guarantee is a bounded application-level read (at most `max_file_size + 1` bytes) plus a post-parse check of the declared `Content-Length`; Bottle's request machinery may still buffer the body up to `BaseRequest.MEMFILE_MAX` (10MB in `spellbookserver.py`) and spill to a `TemporaryFile` beyond that. `upload_file` uses `get_max_file_size()` and `transcribe` uses `get_max_file_size_transcribe()`; both return HTTP 413 with a JSON error when the size is exceeded.
